# Narration script: From bits to blocks

One paragraph per step of the video: 7 chapters, 29 paragraphs. Record each paragraph as its own clip (or one file per chapter with a clear pause between paragraphs), in a warm, calm, natural female English voice at a relaxed pace.

## Chapter 1: Hashes

1.1  A hash is a collection of bits, zeros and ones, inside a computer. But it is shown to humans as a fixed-length string of letters and numbers.

1.2  Reading a long sequence of zeros and ones is hard for people. So computers translate groups of bits into a text format called hexadecimal encoding.

1.3  Hexadecimal uses sixteen symbols: the numbers zero to nine, and the letters A to F. That makes a hash far easier to read than the two hundred fifty-six or five hundred twelve bits behind it.

1.4  Every group of four bits is called a nibble, and every nibble turns into a single letter or number in hexadecimal.

1.5  A 256-bit block hash is sixty-four hex characters, sixty-four times four bits. The leading zeros are what miners search for.


## Chapter 2: Generating hashes

2.1  A hash is generated by passing data of any size through a mathematical algorithm called a hash function.

2.2  A miner using SHA-256, the function of Bitcoin, processes data in blocks of 512 bits, and outputs a hash of exactly 256 bits.

2.3  A miner using BLAKE2b, on Bitcoin BLAKE2b, hashes a restructured 164-byte block header. Every 8 bits make a byte, so that is 1,312 bits of input, while the hash it outputs is still exactly 256 bits.

2.4  The microscopic transistors on a mining chip perform bitwise operations, like AND, XOR and bit-shifting, directly on these streams of bits, billions of times per second.

2.5  When your mining software talks to the hashing hardware, the bits are grouped into bytes: a 256-bit hash travels over the PCIe bus, or another interface, as a 32-byte array.

2.6  When your miner finds a valid share in a pool, the software turns the bits into a hexadecimal string. One hex character is exactly one nibble, so a 256-bit hash travels as a readable 64-character text string.

2.7  Most miners speak the Stratum protocol, to a pool or to their own DATUM Gateway, which packs these hex strings into standard JSON-RPC text messages sent over TCP.


## Chapter 3: Sending a share

3.1  Your mining software receives the work in hexadecimal, built from your node's block template, and converts it into raw binary bytes.

3.2  The raw bytes are fed into the ASIC hashing boards over an internal serial bus.

3.3  The ASIC hashes the bytes and returns a 32-bit nonce, four bytes, when it finds a share.

3.4  The software sends that share back as hex text in a Stratum message, to the pool or through your DATUM Gateway.


## Chapter 4: Hashrate

4.1  Hashrate is the total computing power a proof-of-work network uses to process transactions and mine new blocks: how many hashes per second, all miners together, try.

4.2  The units step up in thousands: hashes per second, kilo, mega, giga, tera, peta, exa and zetta. Each unit is one thousand times the one before.

4.3  A home ASIC does a few hundred terahashes per second. The whole Bitcoin network does around one zettahash per second.


## Chapter 5: Decentralised hashrate

5.1  Decentralised hashrate is the computing power a proof-of-work network uses to process transactions and mine new blocks with locally constructed block templates.

5.2  Every miner decides what goes into the block they work on. Your node builds the block template, DATUM Gateway hands out the work, and your miners hash it.


## Chapter 6: Centralised vs decentralised

6.1  Centralised: miners have little to no visibility or control over which transactions are included or excluded. They merely rent out raw hash power, and a handful of large mining pools decide the contents of most of the network's blocks.

6.2  Decentralised: miners have sovereign control and visibility over which transactions are included or excluded. They run their own Bitcoin full node, such as Bitcoin Knots or Bitcoin Core, and a protocol like DATUM Gateway that talks directly to their mining hardware.


## Chapter 7: How to read the blocks

7.1  The glow around a mined block tells you who built its block template, the list of transactions inside. The colour of the block itself still shows the fees: the warmer, the more its transactions pay.

7.2  On Bitcoin and Bitcoin BLAKE2b, a green glow and Decentralised are only for blocks found by DATUM Gateway verified solominers of pools that are one hundred percent DATUM. The miner built the block template on their own node.

7.3  An orange glow and DATUM Compatible mean a pool that lets its miners build their own templates with their own node and DATUM Gateway: OCEAN on Bitcoin, CONVOY on Bitcoin BLAKE2b. The pool gives miners the choice.

7.4  A red glow and Centralised are for every other pool. The pool builds the block template, so the pool decides which transactions go in, and its miners only rent out hash power.

7.5  On Monero a block never names its pool, so the glow comes from how the reward was paid. A P2Pool block pays every miner directly inside the block: green, Decentralised. Every other Monero block pays a single address, the pool: red, Centralised.

7.6  Every mined Dogecoin block gets the red glow and Centralised, because Dogecoin pools build the block templates for their miners.
